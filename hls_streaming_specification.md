# Спецификация HLS стриминга для видеоплатформы

## Общие положения

HLS (HTTP Live Streaming) - протокол потоковой передачи медиафайлов через HTTP, разработанный Apple. Он поддерживает адаптивный битрейт, позволяя клиенту автоматически выбирать качество видео в зависимости от пропускной способности сети.

## Процесс обработки видео

### 1. Прием видеофайла

После успешной загрузки видео через `/api/videos/upload`, система должна запустить процесс обработки:

1. Валидация видеофайла (формат, кодеки, размер)
2. Извлечение метаданных (разрешение, продолжительность, битрейт)
3. Генерация уникального идентификатора для HLS плейлистов
4. Запуск процесса транскодирования

### 2. Транскодирование

Видео должно быть преобразовано в несколько разрешений:

#### Поддерживаемые разрешения:
- 1080p (1920x1080)
- 720p (1280x720)
- 480p (854x480)
- 360p (640x360)

#### Технические параметры:
- Кодек видео: H.264 (AVC)
- Кодек аудио: AAC
- Частота кадров: 30 FPS (при необходимости понижается)
- Время сегмента: 10 секунд
- Битрейт:
  - 1080p: 5000 kbps
  - 720p: 2800 kbps
  - 480p: 1400 kbps
  - 360p: 800 kbps

### 3. Сегментация

Каждое транскодированное видео разбивается на сегменты:

- Формат сегментов: MPEG-TS (.ts)
- Длительность сегмента: 10 секунд
- Имя файла сегмента: `{video_id}_{resolution}_{segment_index}.ts`

### 4. Генерация плейлистов

#### Мастер плейлист (master.m3u8)
Содержит ссылки на все доступные варианты качества:

```m3u8
#EXTM3U
#EXT-X-VERSION:3

#EXT-X-STREAM-INF:BANDWIDTH=800000,RESOLUTION=640x360,CODECS="avc1.42e01e,mp4a.40.2"
stream_360p.m3u8

#EXT-X-STREAM-INF:BANDWIDTH=1400000,RESOLUTION=854x480,CODECS="avc1.42e01e,mp4a.40.2"
stream_480p.m3u8

#EXT-X-STREAM-INF:BANDWIDTH=2800000,RESOLUTION=1280x720,CODECS="avc1.42e01e,mp4a.40.2"
stream_720p.m3u8

#EXT-X-STREAM-INF:BANDWIDTH=5000000,RESOLUTION=1920x1080,CODECS="avc1.42e01e,mp4a.40.2"
stream_1080p.m3u8
```

#### Вариантные плейлисты (stream_{resolution}.m3u8)
Для каждого разрешения создается отдельный плейлист:

```m3u8
#EXTM3U
#EXT-X-VERSION:3
#EXT-X-TARGETDURATION:10
#EXT-X-MEDIA-SEQUENCE:0

#EXTINF:10.0,
{video_id}_{resolution}_00001.ts
#EXTINF:10.0,
{video_id}_{resolution}_00002.ts
#EXTINF:10.0,
{video_id}_{resolution}_00003.ts

#EXT-X-ENDLIST
```

## Структура хранения файлов

```
/video_storage/
├── {video_id}/
│   ├── master.m3u8              # Мастер плейлист
│   ├── stream_360p.m3u8         # Плейлист 360p
│   ├── stream_480p.m3u8         # Плейлист 480p
│   ├── stream_720p.m3u8         # Плейлист 720p
│   ├── stream_1080p.m3u8        # Плейлист 1080p
│   ├── {video_id}_360p_00001.ts # Сегмент 360p #1
│   ├── {video_id}_360p_00002.ts # Сегмент 360p #2
│   └── ...                      # Остальные сегменты
└── ...
```

## Новый эндпоинт для статуса обработки

#### GET `/api/videos/{videoId}/processing-status`
Получение статуса обработки видео
```json
// Response
{
  "status": "processing|completed|failed",
  "progress": "number (0-100)", // только для processing
  "resolutions": [ // доступные разрешения после обработки
    "360p",
    "480p",
    "720p",
    "1080p"
  ],
  "error_message": "string (optional)" // только для failed
}
```

## Дополнительные требования

### 1. Хранение
- Использовать CDN для доставки сегментов видео
- Реализовать систему хранения с поддержкой горячего/холодного хранилища
- Автоматическое удаление временных файлов после обработки

### 2. Масштабирование
- Горизонтальное масштабирование обработчиков транскодирования
- Очередь задач для обработки видео (Redis/RabbitMQ)
- Мониторинг нагрузки на обработчики

### 3. Кэширование
- Кэширование мастер плейлистов на 1 минуту
- Кэширование вариантных плейлистов на 5 минут
- Использование ETag для проверки изменений

### 4. Безопасность
- Подпись URL сегментов для предотвращения хотлинкинга
- Ограничение количества одновременных потоков на пользователя
- Защита от DDoS атак на эндпоинты стриминга

### 5. Мониторинг
- Логирование всех ошибок транскодирования
- Метрики времени обработки видео
- Алерты при превышении очереди обработки

## Интеграция с фронтендом

### HLS URL
После завершения обработки видео, в объекте видео должен быть доступен URL для HLS стриминга:

```
GET /api/videos/{videoId}
Response:
{
  "id": "string",
  "title": "string",
  // ... другие поля
  "hls_url": "/streaming/{videoId}/master.m3u8",
  "processing_status": "completed"
}
```

### Прогресс обработки
Фронтенд должен регулярно опрашивать эндпоинт статуса обработки и показывать прогресс пользователю:

```
// Пока видео обрабатывается
{
  "status": "processing",
  "progress": 65,
  "resolutions": []
}

// После завершения обработки
{
  "status": "completed",
  "progress": 100,
  "resolutions": ["360p", "480p", "720p", "1080p"]
}
```
