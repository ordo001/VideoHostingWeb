Создай backend для веб-приложения видеохостинга (аналог YouTube), реализующий полноценное API для фронтенда.

Технологический стек:

* ASP.NET Core Web API (C#)
* PostgreSQL (основная база данных)
* S3-совместимое хранилище (MinIO) для видео и thumbnail
* RabbitMQ (брокер сообщений)
* BackgroundService (Worker) для обработки видео

Архитектура:

* Чистая архитектура (Clean Architecture или Onion Architecture)
* Разделение на слои:

  * API (Controllers)
  * Application (бизнес-логика, CQRS опционально)
  * Domain (сущности)
  * Infrastructure (БД, S3, RabbitMQ)
* Использовать Dependency Injection
* DTO + AutoMapper (или аналог)
* Валидация (FluentValidation)

---

Функциональность API:

1. Аутентификация и пользователи:

* Регистрация / логин (JWT)
* Получение профиля
* Получение канала пользователя

---

2. Видео:

* Загрузка видео:

  * загрузка файла в MinIO
  * загрузка thumbnail
  * сохранение метаданных (название, описание, автор)
  * публикация события в RabbitMQ для обработки видео


3. Обработка видео (Worker Service):

* Подписка на очередь RabbitMQ
* Обработка видео:

  * конвертация (например, в mp4 H.264)
  * генерация thumbnail (если не загружен)
  * извлечение длительности
* Сохранение обработанных файлов в MinIO
* Обновление статуса видео:

  * Processing
  * Ready
  * Failed

---

4. Комментарии:

* Добавление комментария
* Получение списка комментариев (с пагинацией)
* Привязка к видео и пользователю

---

5. Лайки / дизлайки:

* Поставить лайк
* Поставить дизлайк
* Убрать реакцию
* Подсчёт количества

---

6. Админ-панель:

* Получение списка пользователей
* Получение видео пользователя
* Удаление видео

---

Работа с MinIO:

* Хранение:

  * исходных видео
  * обработанных видео
  * thumbnail
* Генерация публичных URL или presigned URL

---

RabbitMQ:

* Очередь: video-processing
* Сообщение содержит:

  * videoId
  * путь к файлу
* Worker обрабатывает и обновляет статус

---

База данных (PostgreSQL)

Дополнительно:

* Обработка ошибок (middleware)
* Swagger документация
* Docker Compose (PostgreSQL, MinIO, RabbitMQ)

---

Требования к коду:

* Чистый, расширяемый и production-ready
* Разделение ответственности
* Асинхронность (async/await)
* Использование best practices ASP.NET

---

Результат:

* Полностью готовый backend проект
* Возможность запуска через Docker
* API полностью покрывает потребности frontend части видеохостинга
